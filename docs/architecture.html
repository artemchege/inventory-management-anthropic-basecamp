System architecture

Factory Inventory Management

A two-process demo: a Vue 3 single-page app talks over plain HTTP to a FastAPI service that filters seven JSON files held in memory. There is no database and no auth. Reads dominate: every GET serves lists parsed once at import. One write path exists — restocking orders are appended to a runtime list that a restart clears.

frontend localhost:3000 backend localhost:8001 docs /docs run uv run python main.py  /  npm run dev

What happens when a filter changes

This is the one path that matters — every screen in the app is a variation on it.

  1. The user picks a value in FilterBar. The four selects are bound to refs that live at module scope in useFilters.js, so mutating one updates every consumer at once.client/src/composables/useFilters.js:4-7
  2. Each mounted view reacts. Views set up a watch on the shared refs and re-fetch; they never talk to each other.client/src/views/*.vue — ref + onMounted + watch
  3. api.js builds the query. getCurrentFilters() hands over an object; the api module drops any value equal to all and serializes the rest with URLSearchParams.client/src/api.js:6-72
  4. FastAPI filters in Python. The handler runs apply_filters(), then filter_by_month() where a time dimension exists, over the module-level lists — list comprehensions, no query engine.server/main.py:17-46
  5. Pydantic validates the response. response_model shapes and type-checks each record on the way out, so a JSON field that drifts from its model raises here rather than in the browser.server/main.py:58-110
  6. The view derives everything else. Raw rows land in refs; KPIs, chart series, and totals are computed properties over those refs. Nothing derived is ever stored.Dashboard.vue is the largest example at 1,271 lines

The filter contract

Four filters are global to the app, but not every endpoint honours all four — the mismatch is deliberate and worth knowing.

FilterClient refQuery paramApplies to
Time PeriodselectedPeriodmonthOrders, dashboard summary. Accepts 2025-03 or Q1-2025; ignored by inventory, which has no date field.
LocationselectedLocationwarehouseInventory, orders, dashboard summary
CategoryselectedCategorycategoryInventory, orders, dashboard summary
Order StatusselectedStatusstatusOrders and the order half of the dashboard summary only

Demand, backlog, spending, and reports take no filters at all — those views render the full dataset regardless of what the bar says.

Sharp edges

Things the code does that the structure above would not lead you to expect. Verified against the current tree.

Gap
The client calls endpoints the server does not have. api.js exposes task and purchase-order methods against /api/tasks and /api/purchase-orders; the FastAPI app defines neither. App.vue calls getTasks() on mount, the 404 is swallowed by a catch, and the Tasks modal quietly falls back to the hardcoded list in useAuth.js.client/src/api.js:77-105 · client/src/App.vue:89-95
Gap
Backlog.vue is unreachable. The view exists and fetches data, but no route registers it. Backlog detail is only visible through the modal on the Dashboard.client/src/main.js:12-21
Drift
Reports bypasses the api module. Reports.vue imports axios directly and hardcodes http://localhost:8001 twice, so the single-source-of-truth base URL in api.js is not actually single.client/src/views/Reports.vue:128, 156, 162
Drift
has_purchase_order is always false. The backlog endpoint cross-references purchase_orders.json, which ships as an empty array and has no route that can add to it.server/main.py:161-171
By design
Restocking orders never reach the customer order feed. They live in their own runtime list behind /api/restocking/orders, so they cannot inflate dashboard revenue, quarterly fulfilment rates, or the Orders status counts. The Orders view renders them in a separate section.server/main.py — submitted_restock_orders
By design
Time Period does nothing on Inventory. Stock records carry no date, so /api/inventory accepts only warehouse and category. The filter bar still shows the control on that page.server/main.py:118-125
By design
CORS is open and there is no auth. allow_origins=["*"] with credentials enabled, and the signed-in user is a constant in the client. Correct for a workshop demo, not for anything deployed.server/main.py:49-55 · client/src/composables/useAuth.js
By design
Currency is a display conversion, not a rate. Switching to Japanese multiplies every USD figure by a constant 150 at render time; no value is stored in JPY.client/src/utils/currency.js:3
